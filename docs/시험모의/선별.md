# 모의고사 제작 가이드

이 문서는 가능한 작업 흐름을 설명한다. 문항 선정 방식, 분량, 주제 배분, 재출제 여부,
파일 구성과 자동화 수준은 사용자 목표와 학습 상태에 맞춰 에이전트가 판단한다.

## 정확성 기준

- 범위는 조달청 표준교재와 공식 시험 안내를 기준으로 잡는다.
- 기존 문제은행 문항을 사용하면 지문·선지·정답을 원자료와 대조한다.
- 자체 작성하거나 변형한 문항도 사용할 수 있다. 이 경우 기존 문항 ID를 가장하지 않고
  `custom` 유형 등으로 구별하며, 정답을 뒷받침하는 근거를 남긴다.
- 한 회차 안에서는 문항 ID와 번호가 중복되지 않아야 하며 문제지·정답지·manifest의
  번호와 정답이 일치해야 한다.
- 출처가 불확실하거나 서로 충돌하면 확인 후 사용하고, 해결되지 않으면 해당 문항을
  제외하거나 불확실성을 명시한다.

문항은 직접 고르거나 코드·검색·통계 도구로 보조할 수 있다. O/X, 단답형, 사례형,
`Check Q&A`, 문제은행 문항, 자체 문항을 목적에 맞게 섞을 수 있고, 오답 복습을 위해
기존 문항을 다시 사용할 수도 있다. 다양한 범위를 다루는 것이 유용한 경우에는 Part와
Chapter의 쏠림 및 유사 문항 반복을 검토한다.

## 실제 시험 재현 프로필

“실전 모의고사” 또는 기존 CBT의 공식 프로필로 제작할 때만 다음 형식을 적용한다.

| 프로필 | 구성 | 문항 | 시간 |
|---|---|---:|---:|
| `full` | 1과목 30 + 2과목 20 + 3과목 30 | 80 | 120분 |
| `subject1` | 1과목 | 30 | 45분 |
| `subject2` | 2과목 | 20 | 30분 |
| `subject3` | 3과목 | 30 | 45분 |

기존 필기 CBT는 4지선다 입력을 기대한다. 자유 연습, 보강 퀴즈와 실기 연습에는 이
문항 수·시간·유형을 적용하지 않아도 된다.

## 기존 CBT와 연결할 때

기존 빌더를 사용한다면 각 문항에 다음 추적 정보를 둔다.

```html
<!-- source: 근거를 찾을 수 있는 경로 또는 설명 -->
<!-- id: 과목:part:chapter:stype:qn -->
```

문제은행 원문 유형은 `exam`, `check`, `cqa`, 자체 작성·변형 문항은 `custom`을 사용할
수 있다. 같은 회차에서 ID는 고유해야 한다.

`manifest.json` 예시:

```json
{
  "round": 1,
  "total": 2,
  "items": [
    {"exam_no": 1, "stable_id": "1:1:1:exam:10", "answer": "②"},
    {"exam_no": 2, "stable_id": "1:1:1:custom:1", "answer": "④"}
  ]
}
```

기존 경로는 다음과 같다.

- 통합 필기: `output/mock_exam/필기/통합/<K>회차/`
- 과목별 필기: `output/mock_exam/필기/<N>과목/<K>회차/`
- 실기: `output/mock_exam/실기/<K>회차/`

기존 빌더의 핵심 파일은 `manifest.json`, 문제 Markdown, 정답 Markdown과 생성된
`index.html`이다. 풀이, 피드백, 출제 메모, 분석 자료와 중간 산출물은 필요에 따라
추가하거나 정리한다.

## 검증

완료 전에 작업과 관련된 검사만 선택한다.

```bash
python3 tools/build_cbt_viewer.py --round K --pages
python3 tools/build_cbt_viewer.py --profile subjectN --round K --pages
python3 tools/validate_mock_exam.py
python3 -m unittest discover -s tests -v
```

검증기는 형식과 파일 정합성을 확인하는 도구다. 학습 목적에 맞는 난이도와 문항 구성은
에이전트가 별도로 판단한다.
