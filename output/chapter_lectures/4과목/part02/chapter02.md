# 조달 수요정보 수집하기

수요정보 수집은 검색결과를 즐겨찾기에 쌓는 일이 아닙니다. 공급 가능한 기관과 대상물을 선택할 수 있도록 `원문 위치, 검색조건, 사업단계, 품목, 기관, 시기, 금액, 자격·기술 단서, 갱신일`을 같은 형식으로 기록하는 일입니다. 같은 사업이 발주계획, 사전규격, 입찰공고, 정정공고, 계약정보에 반복해서 나타나므로 연결하지 않으면 건수를 부풀리고 중요한 변경을 놓칩니다.

이 장에서는 전자조달시스템과 조달정보개방포털을 이용해 계획·입찰·계약 정보를 수집하고, 공급대상 수요기관과 조달대상물을 선정할 수 있는 수요정보 대장을 만듭니다. 조달청 표준교재의 데이터 수집과 발주계획 검색 흐름을 따르되, 화면명과 보고서 수는 고정하지 않습니다.

## 이 강의 하나의 완료 기준

다음 열 가지를 수행하면 이 장을 완료한 것입니다.

1. 회사의 공급 가능 범위를 10자리 세부품명·업종·지역·용량·기간으로 정의한다.
2. 발주계획, 사전규격, 공고, 정정, 개찰, 계약정보의 역할을 구분한다.
3. 나라장터, 조달정보개방포털, 기관 자체 전자조달·계약공개시스템의 자료원을 설계한다.
4. 검색어 사전을 품명·세부품명·동의어·기관·과업·규격으로 만든다.
5. 검색조건·수집시각·원문 URL을 남겨 결과를 재현한다.
6. 같은 사업의 여러 단계 자료를 하나의 사업식별자로 연결한다.
7. 취소·정정·재공고·중복·결측을 구분한다.
8. 수요정보를 기관·대상물·단계·시기·규모·적합도·확실성으로 분류한다.
9. 공급 가능한 수요기관과 대상물을 근거로 우선순위화한다.
10. 완성된 수요정보 대장과 수집 로그를 인수인계 가능한 상태로 만든다.

## 공식 수행능력표

| 공식 세세항목 | 이 강의의 학습 결과 | 확인 산출물 |
|---|---|---|
| 공급 가능한 수요기관과 조달대상물 선정하기 위해 수요기관의 발주계획 정보를 수집할 수 있다. | 계획의 목적·수량 또는 규모·예산·시기·조달방법을 추출하고 자사 공급범위와 대조한다. | 발주계획 수집표 |
| 관련 전자조달시스템을 활용하여 공급정보, 공급계획 수립에 필요한 정보를 수집할 수 있다. | 계획부터 계약까지 공식 전자정보를 검색·다운로드·연결한다. | 전자조달 수집로그 |
| 수요정보를 체계적으로 분류하고 문서화할 수 있다. | 표준필드·분류코드·증거등급·갱신주기로 수요정보를 관리한다. | 수요정보 관리대장 |

## 오늘의 사례: 검색결과 27건이 실제 기회 27건인가

`누리클린`은 공공청사 청소용역을 공급합니다. 담당자는 나라장터에서 `청소`, `시설관리`, `환경미화`를 검색하여 27건을 찾았습니다. 이 중 8건은 같은 사업의 발주계획·사전규격·본공고였고, 3건은 정정공고, 2건은 취소, 5건은 회사가 보유하지 않은 법정 업종이나 지역조건을 요구했습니다. 일부 사업은 물품 구매가 주목적이어서 누리클린의 용역 범위와 달랐습니다.

검색결과 행 수는 수요 건수가 아닙니다. 사업단계를 연결하고, 중복·취소를 처리하고, 자격·지역·인력·수행범위를 적용해야 `공급 가능한 수요정보`가 됩니다.

## 1. 공급 가능 범위를 먼저 정의한다

수집 범위는 회사의 희망이 아니라 증빙 가능한 능력으로 정합니다.

| 범위축 | 정의 질문 | 증거 |
|---|---|---|
| 조달대상물 | 어떤 물품 세부품명, 용역 업종·과업, 공사 업종·주력분야인가? | 등록증, 면허, 제품·서비스 목록 |
| 기술범위 | 필수 성능·인증·인력·장비의 상한은? | 시험·인증, 인력·장비 현황 |
| 수량·금액 | 동시 생산·수행 가능한 용량과 현금한도는? | 생산·인력계획, 자금계획 |
| 지역 | 운송·설치·현장관리 가능한 지역은? | 물류망, 지사·협력체계 |
| 기간 | 제안·제작·납품·착수에 필요한 최소기간은? | 표준 일정, 과거 실적 |
| 위험한도 | 보증, 지체, 재고, 가격변동을 어디까지 감수하는가? | 내부 승인기준 |

예를 들어 `청소용역`처럼 넓은 단어만 쓰면 건물관리, 폐기물처리, 방역, 물품 구매가 함께 검색될 수 있습니다. 회사의 실제 업종, 과업범위, 제외어까지 검색사전에 넣습니다.

## 2. 검색사전과 자료원 지도를 만든다

### 2.1 검색사전

| 사전 유형 | 구성 | 예시 활용 |
|---|---|---|
| 공식 분류어 | 10자리 세부품명, 물품분류번호, 업종·업종코드 | 정확한 등록범위 검색 |
| 표준 과업어 | 과업명, 시설·서비스 유형, 필수 작업 | 용역·공사 내용 검색 |
| 현장 용어 | 약칭, 동의어, 구어, 옛 명칭 | 제목 누락 방지 |
| 규격어 | 성능, 재질, 용량, 인증, 모델 속성 | 기술 적합 대상 좁히기 |
| 기관어 | 기관명, 산하기관, 사업부서, 지역 | 반복 수요처 추적 |
| 제외어 | 자사 범위 밖 품목·과업 | 오탐 감소 |

검색어마다 `포함 이유`, `제외 이유`, `마지막 검토일`을 기록합니다. 공고에서 새 표현을 발견하면 사전을 갱신하되, 과거 검색결과와 비교할 수 있도록 버전을 남깁니다.

### 2.2 공식 자료원 지도

| 자료원 | 얻을 정보 | 수집방식 | 재확인 |
|---|---|---|---|
| 나라장터 발주계획 | 기관, 사업목적, 규모·예산, 예정시기 | 조건검색·원문 확인 | 계획변경 여부 주기 확인 |
| 나라장터 사전규격 | 규격·과업 초안, 예산, 의견제출 단서 | 상세·첨부 다운로드 | 본공고에서 변경 확인 |
| 나라장터 입찰·정정공고 | 자격, 기술, 일정, 방식, 제출자료 | 공고·첨부 원본 저장 | 정정·취소 알림 확인 |
| 개찰·계약정보 | 참가·낙찰·계약상대자·금액·계약기간 | 사업번호로 연결 | 변경계약·이행정보 확인 |
| 조달정보개방포털 | 대량 보고서·공개 API·분석용 데이터 | 파일 또는 API | 필드정의·갱신일 확인 |
| 기관 자체 전자조달·계약공개 | 나라장터 밖 또는 기관 자체 집행 정보 | 공식 시스템 검색 | 나라장터와 중복 여부 확인 |
| 국가법령정보센터·조달청 | 제도·규정·공식 안내 | 원문 URL·시행일 기록 | 개정·시행 여부 확인 |

표준교재는 조달정보개방포털의 보고서, 공개 API, 시각화, 분석기능을 소개합니다. 이 기능들은 수집 목적에 따라 선택합니다. 소수 중요사업은 원문을 직접 읽고, 대량 추세는 보고서·API를 활용하며, 지도·그래프는 분포 탐색에 씁니다. 데이터의 편리함이 원공고 확인을 대신하지는 않습니다.

## 3. 발주계획 정보를 수집한다

국가계약법령상 공개되는 조달계획은 물품·공사·용역의 목적, 수량 또는 규모, 예산 같은 정보를 포함합니다. 실제 화면에는 더 많은 필드가 있을 수 있으나 수집의 최소단위는 다음과 같습니다.

| 분류 | 필드 | 확인 포인트 |
|---|---|---|
| 식별 | 내부 사업ID, 기관코드·명, 사업명 | 동일사업 연결의 기준 |
| 대상 | 품명·세부품명, 과업·공종, 수량·단위 | 자사 범위와 일치 여부 |
| 규모 | 예산액, 추정 규모, 계약기간 | 금액개념과 포함범위 |
| 시기 | 등록일, 발주시기, 예상 공고·납기 | 계획변경과 최신성 |
| 방식 | 조달방식, 계약방법, 집행기관 | 준비경로와 적합성 |
| 담당 | 수요기관, 부서, 문의정보 | 공식 질의·갱신 확인 |
| 출처 | 원문 URL, 수집시각, 검색조건 | 재현성과 감사추적 |

현재 조달청 공식 안내의 나라장터 경로는 `발주 → 발주목록 → 발주계획`입니다. 화면 경로가 달라져도 `발주계획 원문과 상세정보`를 찾는 목적은 같습니다. 2026년도 공식 발주계획도 기관 등록자료를 취합한 것이며 계획조정으로 실제 사업과 달라질 수 있음을 밝힙니다. 그러므로 발주계획에는 반드시 `계획`, `확정 아님`, `다음 확인일`을 표시합니다.

## 4. 계획에서 계약까지 하나의 사업으로 연결한다

같은 사업의 상태는 시간에 따라 바뀝니다.

`발주계획 → 사전규격 → 입찰공고 → 정정·취소 → 개찰 → 계약 → 변경·이행`

각 단계의 번호가 처음부터 모두 존재하지 않을 수 있으므로 연결키를 계층적으로 사용합니다.

1. 공식 연계번호가 있으면 가장 먼저 사용한다.
2. 없으면 기관코드, 사업명, 대상물, 예산, 예정시기 조합으로 후보를 만든다.
3. 첨부 규격과 담당부서, 수량을 대조하여 동일사업인지 확인한다.
4. 확실하지 않으면 병합하지 않고 `연결 미확정`으로 둔다.
5. 본공고가 나오면 계획값을 덮어쓰지 말고 계획값과 확정값을 나란히 보존한다.
6. 정정공고는 최종본 표시와 함께 바뀐 항목·시각을 기록한다.
7. 취소·유찰·재공고는 원사업과 연결하되 건수 산정규칙을 명시한다.

### 증거등급

다음 등급은 법정 분류가 아니라 이 강의의 자체 관리기준입니다.

| 등급 | 상태 | 활용 |
|---|---|---|
| A | 유효한 실제 공고·최종 정정과 첨부 확인 | 입찰 참가판정·단기 자원배치 |
| B | 사전규격 또는 구체적 계약요청 정보 확인 | 기술검토·질의·사전준비 |
| C | 공식 발주계획 확인 | 중기 파이프라인·모니터링 |
| D | 과거 계약실적·정책·예산으로 추정 | 탐색과 가설, 확정계획 아님 |

등급이 높다고 자동으로 적합한 기회는 아닙니다. A등급 공고도 자격이나 기술을 충족하지 못하면 제외합니다.

## 5. 수요정보를 정제한다

### 5.1 중복·정정·취소

| 상황 | 처리 | 수요 건수 |
|---|---|---|
| 발주계획과 본공고가 연결됨 | 한 사업 아래 단계별 기록 | 기본적으로 한 기회로 관리 |
| 정정공고 | 원공고에 버전 연결, 변경필드 표시 | 별도 신규기회로 세지 않음 |
| 취소공고 | 상태를 취소로 보존 | 활성수요에서 제외 |
| 유찰 후 재공고 | 원사업 연결, 조건변경 비교 | 분석목적에 따라 공고 횟수와 사업 수를 구분 |
| 분할발주 | 실제 독립 계약인지 확인 | 계약단위별 기회와 총사업 관계를 함께 기록 |
| 기관·사업명 유사 | 공식 번호와 첨부 비교 | 근거 없이는 병합하지 않음 |

### 5.2 결측과 단위

빈 금액은 0원이 아니며, 수량 `1식`은 1개가 아닙니다. 금액·수량·기간의 결측을 `미상`, `비공개`, `해당없음`으로 구분합니다. 예산, 추정가격, 기초금액, 계약금액을 같은 열에 섞지 않습니다. 부가가치세·옵션·설치·운송 포함 여부도 메모합니다.

## 6. 공급 가능한 기관과 대상물을 선정한다

수집 후 다음 두 번의 필터를 적용합니다.

### 6.1 필수 적합성 필터

| 필터 | 통과 질문 |
|---|---|
| 등록·법률 | 세부품명·업종·면허·기업구분 등 필수자격을 기준일까지 충족 가능한가? |
| 기술 | 필수규격·인증·과업을 충족하는가? |
| 수행 | 수량·인력·장비·지역·납기·A/S를 감당하는가? |
| 경제 | 비용·보증·현금흐름을 고려해 입찰검토 가치가 있는가? |
| 일정 | 등록·질의·제안·투찰 준비시간이 있는가? |

하나의 필수조건이 불가능하면 우선순위 점수로 덮지 않고 제외하거나 보류합니다.

### 6.2 우선순위 점수

필수 필터를 통과한 수요만 비교합니다. 자체 기준의 예는 다음과 같습니다.

| 요소 | 질문 | 평가 예 |
|---|---|---|
| 반복성 | 동일기관·품목의 반복 수요인가? | 높음·중간·낮음 |
| 확실성 | 계획·사전규격·공고 중 어느 단계인가? | A~D 증거등급 |
| 전략성 | 목표시장 진입·실적 확보에 도움이 되는가? | 높음·중간·낮음 |
| 준비여유 | 필수 자료와 공급능력을 준비할 시간이 있는가? | 충분·조건부·부족 |
| 집중위험 | 특정기관·단일 대형건 의존이 큰가? | 낮음·중간·높음 |

가중점수를 쓸 수 있지만 가중치는 회사의 전략에 따라 정하고 승인일·승인자를 기록합니다. 점수는 판단을 돕는 도구이지 필수자격 미충족을 합격으로 바꾸는 장치가 아닙니다.

## 7. 체계적으로 분류하고 문서화한다

수요정보 대장은 다음 분류를 동시에 가집니다.

- 기관: 기관유형, 기관코드, 지역, 담당부서
- 대상물: 물품·용역·공사, 품명·세부품명, 업종·공종, 규격
- 단계: 계획, 사전규격, 공고, 정정, 개찰, 계약, 취소
- 시간: 수집일, 발주시기, 공고·마감·납품일, 다음 확인일
- 규모: 수량·단위, 예산·추정·계약금액의 구분
- 적합성: 자격, 기술, 수행, 경제, 일정의 통과·보류·제외
- 증거: 공식 URL, 첨부파일, 검색조건, 증거등급
- 책임: 담당자, 후속조치, 기한, 최종검토자

원본은 수정하지 않고 보존하고, 분석용 정제본에는 변환 규칙과 버전을 둡니다. 개인정보나 비공개자료를 불필요하게 복제하지 않으며 공개범위와 저장정책을 따릅니다.

## 9. 필답형 답안 프레임

### 유형 A: 발주계획 수집

> 먼저 자사의 공급범위를 세부품명·업종·기술·지역·용량·기간으로 정한다. 공식 전자조달시스템에서 기관·품목·과업·기간 검색어를 사용하여 발주계획을 찾고, 기관·사업목적·대상물·수량 또는 규모·예산·예정시기·조달방법을 추출한다. URL·수집일시·검색조건을 기록하고 계획변경 가능성과 다음 확인일을 표시한다. 이후 사전규격·본공고·정정·계약정보를 같은 사업ID로 연결해 갱신하며 자격·기술·수행·경제·일정 필터를 통과한 기관과 대상물을 선정한다.

### 유형 B: 수요정보 문서화

> 원본은 보존하고 정제본을 별도로 만든다. 기관코드, 대상물 분류, 사업단계, 시기, 수량·단위, 금액개념, 자격·기술 단서, 공식 출처, 증거등급, 적합성, 담당자·갱신일을 표준필드로 기록한다. 동일사업의 계획·사전규격·공고·정정·계약을 연결하고 취소·유찰·재공고를 구분한다. 결측을 0으로 바꾸지 않으며 변경이력과 정제규칙을 남긴다.

## 10. 자체 제작 문제 10선

아래 문제는 자체 제작이며 총점은 30점입니다.

### 문제

1. **단답형 3점**: 공급 가능 범위를 정하는 여섯 축을 쓰시오.
2. **O/X 2점**: 검색결과의 행 수는 곧 독립된 수요사업의 건수이다.
3. **서술형 3점**: 검색사전에 공식 분류어 외에 동의어·제외어가 필요한 이유를 쓰시오.
4. **선택형 2점**: 계획과 본공고를 연결할 가장 강한 근거는? ① 비슷한 제목 ② 공식 연계번호 ③ 같은 달 ④ 같은 금액대
5. **단답형 3점**: 발주계획에서 수집할 최소 정보 여섯 가지를 쓰시오.
6. **사례형 4점**: 원공고, 정정공고 두 건, 취소공고가 검색됐다. 관리대장과 활성수요 건수를 어떻게 처리할지 쓰시오.
7. **O/X 2점**: 수량이 `1식`이면 개별 제품 수량 1개로 환산한다.
8. **서술형 4점**: 증거등급 A~D의 의미를 설명하시오.
9. **사례형 4점**: 필수면허가 없지만 반복성과 예상금액이 큰 사업의 우선순위 점수가 가장 높다. 선정해도 되는지 설명하시오.
10. **단답형 3점**: 수요정보 대장에 포함할 관리분류 일곱 가지를 쓰시오.

### 정답과 채점기준

1. **정답:** 대상물, 기술, 수량·금액, 지역, 기간, 위험한도. 각 0.5점.
2. **정답:** X. 단계 중복·정정·재공고 등이 섞일 수 있음. 2점.
3. **채점:** 제목·현장용어의 표현 차이 포착 1점, 누락 감소 1점, 제외어로 오탐 감소 1점.
4. **정답:** ②. 2점.
5. **예시답:** 기관, 사업목적, 대상물, 수량·규모, 예산, 예정시기, 조달·계약방법, 출처 중 여섯. 각 0.5점.
6. **채점:** 하나의 사업ID로 연결 1점, 정정 버전과 변경사항 보존 1점, 취소상태 표시 1점, 활성수요에서는 제외 1점.
7. **정답:** X. 구성내역을 확인하기 전 개수로 환산할 수 없음. 2점.
8. **채점:** A 실제 공고·최종 정정 1점, B 사전규격 등 구체 정보 1점, C 공식 발주계획 1점, D 과거실적·정책 기반 추정 1점.
9. **채점:** 선정 불가 또는 보류 1점, 필수요건은 점수로 상쇄 불가 1점, 기준일까지 적법한 충족 가능성 확인 1점, 불가능하면 제외 1점.
10. **예시답:** 기관, 대상물, 단계, 시간, 규모, 적합성, 증거, 책임 중 일곱. 타당한 항목당 약 0.43점, 최대 3점.
