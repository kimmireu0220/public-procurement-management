> 자체 제작 강의입니다. 전자조달 화면·메뉴명은 개편될 수 있으므로 특정 버튼 위치를 외우기보다 업무 흐름, 확인자료, 완료증거와 장애 대응을 학습합니다. 실제 제출 전에는 해당 시스템의 최신 조달업체 매뉴얼과 공고를 우선 확인하십시오.

## 이 강의 하나의 완료 기준

이 단원의 질문은 **“전자조달에서 조회부터 대금청구까지, 어떻게 누락 없이 처리하고 완료를 입증할 것인가?”**입니다. 학습 후에는 다음을 할 수 있어야 합니다.

- 입찰공고·참가자격등록·계약현황을 목적에 맞게 조회한다.
- 입찰서 제출, 전자계약, 대금청구의 준비·실행·완료확인을 수행한다.
- 외부 시스템의 정보를 식별키와 기준일로 연결한다.
- 오류를 업무오류·권한오류·기술오류로 분류하고 안전하게 해결한다.

## 공식 출제기준과 학습 결과

| 공식 수행능력 | 학습 결과 |
|---|---|
| 공고·참가자격등록·계약현황 조회 | 검색조건과 조회결과를 공고검토표로 남긴다. |
| 입찰서 제출·계약체결·대금청구 수행 | 단계별 사전점검과 접수·완료증거를 관리한다. |
| 외부 시스템 연계·통합 활용 | 동일 주체·품목·공고를 식별키로 연결하고 출처 차이를 기록한다. |
| 오류·문제 해결방법 적용 | 오류분류표와 장애대응 기록으로 복구·대체절차를 실행한다. |

## 시작 사례

한빛산업은 마감 당일 가격입찰서를 제출하려 한다. 담당자 인증수단은 정상처럼 보이지만 회사 대표자 정보가 최근 바뀌었고, 첨부파일 중 하나는 최종본인지 확실하지 않다. 제출 버튼을 누른 뒤 화면이 멈췄고 담당자는 “아마 접수됐을 것”이라 생각하고 창을 닫았다.

이 상황에서 가장 위험한 말은 “아마”입니다. 시스템 업무는 화면을 한 번 눌렀다는 사실이 아니라, **현재 자격정보와 제출내용이 공고요건에 맞고 시스템이 접수·완료했다는 증거**로 끝납니다.

## 1. 전자조달 업무의 공통 골격

`식별 → 조회 → 대조 → 준비 → 사전점검 → 실행 → 접수확인 → 보존·추적`

| 단계 | 핵심 질문 | 완료증거 |
|---|---|---|
| 식별 | 어떤 기관·공고·차수·업무인가? | 공고번호·차수·업무구분 |
| 조회 | 최신 공고와 자기정보를 찾았는가? | 조회일시·검색조건·결과 |
| 대조 | 공고와 업체·제품·업종 정보가 일치하는가? | 자격대조표 |
| 준비 | 입력값·첨부·결재·인증이 준비됐는가? | 제출패키지·승인기록 |
| 사전점검 | 마감·권한·환경·파일을 재확인했는가? | 체크리스트 |
| 실행 | 정확한 업무에서 최종 전송했는가? | 전송시각·처리상태 |
| 접수확인 | 접수번호·전자문서 상태가 확정됐는가? | 접수증·송수신 기록 |
| 보존·추적 | 결과와 후속기한을 관리하는가? | 원본·해시·후속업무표 |

메뉴 이름이 바뀌어도 이 골격은 유지됩니다. 시험 답안에도 `접속하여 처리한다`로 끝내지 말고 입력, 검증, 전송, 접수확인과 증거 보존을 씁니다.

### 전자문서의 송신·수신 시점

전자조달법 제11조의 원칙은 **전자문서가 전자조달시스템에 입력된 때 송신·수신된 것으로 본다**는 것입니다. 시스템 밖의 전산장비에만 입력된 문서는 출력 여부와 관계없이 수신되지 않은 것으로 보고, 시스템에 입력된 문서는 송신자의 내심과 관계없이 송신된 것으로 봅니다. 따라서 작성완료·이메일 발송·업로드 시도와 시스템 입력·접수는 구분해야 합니다.

전자조달이용자가 제출한 전자입찰서는 시스템 입력시점을 확인할 수 없더라도 법이 정한 전자서명인증사업자 제시시점이 확인되면 그 시점을 수신시점으로 볼 수 있는 예외가 있습니다. 이 예외를 임의의 PC 저장시각이나 화면 캡처에 확대하지 않습니다. 같은 조가 요구하는 전자서명과 실제 시스템의 접수·제출내역을 함께 확인합니다.

## 2. 조회 업무 세 가지

### 입찰공고 조회

| 검색축 | 확인 내용 |
|---|---|
| 식별 | 공고번호, 차수, 정정·취소 여부 |
| 대상 | 업무구분, 품명·세부품명, 업종, 수요기관 |
| 일정 | 게시, 질의, 설명회, 제출, 개찰 등 공고가 정한 시각 |
| 방법 | 계약·낙찰방법, 공동수급, 제출방식 |
| 문서 | 공고문, 규격·과업, 평가기준, 계약조건, 정정첨부 |

검색결과 목록만 보고 결정하지 않습니다. 상세공고와 모든 첨부, 정정이력을 열어 한 묶음으로 저장합니다. 차수가 다르면 요구사항과 마감이 달라질 수 있으므로 식별자 전체를 기록합니다.

### 참가자격등록 조회

- 상호·대표자·주소 등 업체 기본정보
- 등록된 세부품명·제조/공급 범위
- 공사·용역 업종과 필요한 주력분야
- 입찰대리인, 인증·권한 상태
- 직접생산·기업확인 등 공고가 요구한 외부 증빙과 시스템 연계상태
- 등록·면허·증빙의 공고상 기준일 충족 여부

시스템에 표시된 정보가 실제 최신 상태와 다르면 그대로 제출하지 않습니다. 변경·등록 절차, 반영시간과 공고 기준일을 확인합니다.

### 계약현황 조회

계약번호·변경차수, 계약금액·기간, 계약문서 송수신, 보증, 납품·검사, 세금계산·청구·지급의 현재 상태와 다음 행위를 확인합니다. 목록의 `진행 중` 표시만 보지 말고 지연 원인과 상대방 처리상태를 세부 문서에서 확인합니다.

## 3. 입찰서 제출 절차

### 제출 전 패키지

| 묶음 | 점검 내용 |
|---|---|
| 자격 | 공고상 모든 참가조건, 기준일, 자기정보 일치 |
| 가격 | 금액·단위·부가세 처리, 산출내역과 승인금액 일치 |
| 기술 | 제안서·규격서 요구 형식, 페이지·용량·파일 무결성 |
| 공동수급·대리 | 구성원 승인, 분담내용, 제출자 권한 |
| 보증·서약 | 공고가 요구한 방식과 전자제출 여부 |
| 시간·환경 | 시스템 시간 기준, 브라우저·보안모듈·네트워크·인증 상태 |

### 제출 실행

1. 최신 공고번호와 차수를 다시 확인한다.
2. 제출업무 유형과 제출자를 확인한다.
3. 입력값과 첨부파일 이름·내용·크기·열림 여부를 검사한다.
4. 전자서명·인증 전 최종 미리보기와 내부 승인본을 대조한다.
5. 전송 후 처리상태가 `접수·제출 완료`에 해당하는지 확인한다.
6. 접수번호, 제출시각, 제출내역, 첨부목록과 확인증을 보존한다.
7. 공고가 허용하는 수정·취소와 후속 개찰일정을 확인한다.

마감 직전 전송을 일상적 계획으로 삼지 않습니다. 파일 업로드·인증·공동수급 승인·장애 대응 시간을 포함한 내부 마감시각을 더 앞에 둡니다.

## 4. 전자계약 체결 절차

1. 계약요청·초안을 식별하고 공고·낙찰·협상 결과와 연결한다.
2. 당사자, 계약목적, 금액, 기간, 납품장소, 검사, 보증, 대가·지체·하자 조건을 확인한다.
3. 첨부 계약조건·산출내역·과업·규격·협상문서의 버전과 우선순위를 점검한다.
4. 내부 계약검토와 결재, 전자서명 권한을 확인한다.
5. 보증·인지·그 밖의 요구사항을 공고와 적용규정에 따라 처리한다.
6. 전자서명 후 상대방 서명·계약확정 상태와 확정시각을 확인한다.
7. 확정된 계약문서 전체를 원본 형식으로 보존하고 수행팀에 통제본을 배포한다.

초안을 열람했다는 사실과 계약이 체결됐다는 사실을 구분합니다. 양 당사자의 전자서명과 시스템 최종상태, 확정본을 확인해야 합니다.

## 5. 대금청구 절차

| 단계 | 확인할 것 |
|---|---|
| 청구 가능성 | 납품·성과 완료, 검사·검수 상태, 청구 조건 충족 |
| 금액 산정 | 계약·변경차수, 기성·선금 정산, 공제·세금 반영 |
| 증빙 준비 | 검사·검수, 납품·성과, 세금계산, 계좌·채권 관련 문서 |
| 시스템 작성 | 정확한 계약번호·차수·청구유형·금액·첨부 입력 |
| 전송·확인 | 접수상태, 보완·반려 사유, 처리기관과 후속기한 |
| 입금·정산 | 지급액·지급일·공제내역 대조, 미수·오류 추적 |

공급자 화면에서 청구가 전송됐어도 검사 미완료나 증빙 불일치로 지급 단계가 멈출 수 있습니다. 청구상태와 선행업무를 함께 봅니다.

## 6. 외부 시스템 정보를 안전하게 연계한다

전자조달은 기업·제품·법령·세금·보증·공공데이터 등 외부 정보와 연결됩니다. 통합 활용은 화면 여러 개를 나란히 보는 것이 아니라 동일 대상을 올바르게 결합하는 일입니다.

### 네 가지 연결키

- 기관·업체: 기관코드, 사업자등록번호 등 공인 식별자
- 공고·계약: 공고번호와 차수, 계약번호와 변경차수
- 품목: 물품분류번호·세부품명번호·물품식별번호 등 목적에 맞는 코드
- 시간: 공고일, 기준일, 계약일, 데이터 갱신일

### 연계 검증 다섯 항목

| 항목 | 오류 예시 |
|---|---|
| 주체 일치 | 본점과 지점, 변경 전 대표자 혼동 |
| 대상 일치 | 품명과 세부품명, 제품식별을 혼용 |
| 버전 일치 | 정정 전 공고와 최종 공고 결합 |
| 시간 일치 | 현재 인증을 과거 기준일에도 유효한 것으로 오인 |
| 의미 일치 | `등록`, `인증`, `계약` 상태를 같은 값으로 처리 |

외부 자료가 시스템에 자동 연계되더라도 반영 지연·매핑 오류 가능성을 점검하고, 원 발급기관의 공식 원문과 비교합니다.

## 7. 오류를 세 종류로 나누어 해결한다

| 오류 유형 | 예 | 1차 조치 |
|---|---|---|
| 업무·규칙 오류 | 자격 미충족, 마감 경과, 필수항목 누락, 상태 전제 미완료 | 공고·업무규칙과 선행상태 확인 |
| 권한·인증 오류 | 대리권한, 전자서명, 사용자역할, 공동수급 승인 문제 | 사용자·권한·인증 유효성 확인 |
| 기술·연결 오류 | 접속, 업로드, 화면 멈춤, 응답 지연, 외부연계 실패 | 환경 점검, 재현정보 보존, 공식 지원채널 문의 |

### 장애 대응 7단계

1. 오류시각과 업무, 공고·계약 식별자를 기록한다.
2. 오류문구 전체, 화면, 처리상태와 직전 행위를 보존한다.
3. 마감·권한·자격·필수입력 등 업무오류부터 확인한다.
4. 최신 공식 공지와 매뉴얼에서 알려진 장애·점검을 확인한다.
5. 안전한 범위에서 재로그인, 파일·환경 점검 등 공식 안내된 조치를 적용한다.
6. 해결되지 않으면 공식 지원채널에 식별자·시각·증상을 전달하고 접수기록을 남긴다.
7. 공고와 규정이 인정하는 대체·복구절차가 있는지 계약담당자와 확인하고 결과를 추적한다.

무작정 반복 제출하면 중복·잘못된 상태를 만들 수 있습니다. 이전 전송의 접수 여부부터 조회합니다. 화면 캡처만으로 법적 제출 완료가 자동 인정된다고 가정하지도 않습니다.

## 실습 산출물: 전자업무 실행기록

## 시작 사례 적용

한빛산업은 제출 완료를 확인할 수 없으므로 즉시 같은 공고·차수의 제출내역과 접수상태부터 조회해야 합니다. 대표자 변경의 등록반영과 제출자 권한, 최종 첨부본을 재대조하고 오류시각·화면·네트워크 상태를 보존합니다. 미접수라면 남은 시간 안에 공식 매뉴얼의 안전한 절차로 제출하고, 접수 여부가 불명확하거나 장애가 계속되면 지원채널과 계약담당자에게 식별정보를 제공해 공식 처리방법을 확인합니다. 접수번호·제출내역 없이 `제출했다`고 종결하면 안 됩니다.

## 필답형 답안 프레임

- 조회형: `조회 목적 → 공고·차수·계약 식별 → 검색조건 → 상세·첨부·정정이력 대조 → 기준일 판정 → 조회증거 보존`
- 처리형: `자격·입력·첨부·권한 준비 → 최종 사전점검 → 전자서명·전송 → 접수·확정 상태 확인 → 접수번호·확정본 보존 → 후속기한 추적`
- 연계형: `주체·공고/계약·품목·시간 연결키 → 원 발급기관 출처 → 버전·기준일·의미 일치 → 반영지연·매핑오류 확인`
- 장애형: `이전 접수여부 확인 → 오류시각·문구·상태 보존 → 업무·권한·기술 원인 분류 → 공식 복구·문의 → 대체절차 요건 확인 → 최종 완료증거`

전자업무 답안은 `접속해서 처리한다`로 끝내지 않습니다. 업무 식별, 사전 대조, 권한 있는 전송, 시스템 입력·접수, 완료증거와 오류 후속조치까지 적어야 합니다.

## 자체 제작 연습문제 11선

**문제 1.** **[1점]** O/X: 제출 버튼을 눌렀다면 접수번호가 없어도 입찰서 제출은 완료된 것으로 관리한다.

> **정답·해설:** **X.** 처리상태와 접수번호·제출내역 등 완료증거를 확인해야 한다. 정답이면 1점, 오답·무응답이면 0점.

**문제 2.** **[1점]** O/X: 정정공고가 있으면 공고번호뿐 아니라 차수와 최종 첨부를 확인해야 한다.

> **정답·해설:** **O.** 정정 전 문서와 최종 문서를 섞으면 안 된다. 정답이면 1점, 오답·무응답이면 0점.

**문제 3.** **[1점]** O/X: 외부 인증정보가 화면에 보이면 원 발급기관의 유효성과 기준일을 확인할 필요가 없다.

> **정답·해설:** **X.** 반영지연·매핑 오류와 기준일 불일치를 확인한다. 정답이면 1점, 오답·무응답이면 0점.

**문제 4.** **[8점]** 전자조달 업무 공통 골격 여덟 단계를 쓰시오.

> **정답·해설:** 식별 → 조회 → 대조 → 준비 → 사전점검 → 실행 → 접수확인 → 보존·추적. 각 1점.

**문제 5.** **[4점]** 입찰서 제출 후 보존할 완료증거 네 가지를 쓰시오.

> **정답·해설:** 접수번호, 제출시각, 입력·제출내역, 첨부목록·확인증 중 네 가지. 각 1점.

**문제 6.** **[6점]** 전자계약 초안 열람과 계약체결 완료를 구분하는 기준을 설명하시오.

> **정답·해설:** 초안 열람은 내용을 본 상태이고, 체결 완료는 권한 있는 당사자의 전자서명과 시스템 최종상태 및 확정본을 확인한 상태다.

**문제 7.** **[4점]** 외부 시스템 연계 시 확인할 네 연결키를 쓰시오.

> **정답·해설:** 기관·업체 식별자, 공고·계약 식별자와 차수, 품목 코드, 시간·기준일. 각 1점.

**문제 8.** **[6점]** 오류 세 유형과 각 1차 조치를 쓰시오.

> **정답·해설:** 업무오류는 공고·선행상태, 권한오류는 사용자·인증·대리권, 기술오류는 환경·공지·재현정보와 지원채널을 확인한다.

**문제 9.** **[10점]** 대금청구가 반려됐을 때 확인할 항목을 절차대로 쓰시오.

> **정답·해설:** 계약·변경차수와 청구 선행조건, 검사·검수 상태, 청구금액·공제, 필수 증빙, 반려사유를 확인해 보완하고 재접수 후 상태를 추적한다.

**문제 10.** **[10점]** 시작 사례의 장애 대응을 `상태확인 → 원인분류 → 복구·문의 → 완료입증` 순서로 쓰시오.

> **정답·해설:** 동일 공고·차수의 제출상태를 먼저 조회하고, 자격·권한·파일·마감의 업무오류와 인증·기술오류를 구분한다. 오류증거를 보존한 채 공식 매뉴얼과 지원채널로 복구하고, 재전송 전 이전 접수 여부를 확인한다. 최종 접수번호·제출내역을 저장한다.

**문제 11.** **[9점]** 전자조달법상 전자문서의 원칙적 송신·수신 시점과 시스템 밖 전산장비에 입력된 문서의 효과를 설명하시오.

> **정답·해설:** 전자문서는 원칙적으로 전자조달시스템에 입력된 때 송신·수신된 것으로 본다. 시스템 밖의 전산장비에 입력된 문서는 출력 여부와 관계없이 수신되지 않은 것으로 보므로, 작성·저장·전송시도만으로 시스템 접수를 대신할 수 없다. 전자입찰서의 법정 예외는 적용요건이 확인되는 경우에만 별도로 검토한다.

6번은 초안 열람의 의미 1점, 권한 있는 당사자의 전자서명 2점, 시스템 최종상태 1점, 확정본 확인 1점, 두 상태의 명확한 구분 1점입니다.

8번은 업무·권한·기술 오류의 명칭과 그에 맞는 1차 조치를 각각 1점씩 부여합니다. 오류 유형 하나당 2점입니다.

9번은 계약·변경차수 1점, 청구 선행조건 2점, 검사·검수 1점, 금액·공제 2점, 필수 증빙 1점, 반려사유 확인·보완 2점, 재접수 후 상태추적 1점입니다.

10번은 상태확인 2점, 원인분류 2점, 안전한 조치 2점, 공식 문의·기록 2점, 완료확인 2점입니다.

11번은 전자조달시스템 입력 시 송신·수신된다는 원칙 3점, 시스템 밖 전산장비 입력은 출력 여부와 관계없이 수신되지 않는다는 효과 3점, 작성·저장·전송시도와 시스템 접수의 구분 1점, 전자입찰서 예외는 법정 요건이 확인될 때만 검토한다는 한정 2점입니다.

### 총점·통과선·취약 재학습 기준

- **총점: 60점.** 1~3번 3점, 4~5번 12점, 6~8번 16점, 9~10번 20점, 11번 9점입니다. 4·5·7번은 정답·해설의 요소 하나당 1점이며, 문항 배점을 초과하지 않습니다.
- **권장 통과선: 42점(70%) 이상.** 단, 총점만 넘고 아래 핵심영역 기준을 충족하지 못하면 해당 영역을 재학습합니다.
- **완료원칙 게이트(1~3번): 3점 중 3점 미만**이면 클릭·화면표시와 시스템 접수·완료증거의 차이, 정정 차수, 외부정보 기준일을 다시 학습합니다.
- **기본절차 게이트(4~5번): 12점 중 9점 미만**이면 공통 8단계와 제출 완료증거를 빈 종이에 순서대로 재작성합니다.
- **계약·연계·오류 게이트(6~8번): 16점 중 12점 미만**이면 계약확정의 세 증거, 연결키 4개, 오류유형별 1차 조치를 다시 표로 만듭니다.
- **상황대응 게이트(9~10번): 20점 중 14점 미만**이면 선행상태 확인부터 공식 문의·재접수·완료확인까지 두 사례를 다시 풉니다.
- **법적 효과 게이트(11번): 9점 중 7점 미만**이면 `시스템 입력 시점`, `시스템 밖 입력의 불수신`, `법정 예외의 제한`을 구분해 다시 서술합니다.
- 재학습 후에는 해당 게이트의 전 문항을 다시 풀어 **42점 이상이면서 모든 게이트를 동시에 충족**해야 통과로 판정합니다.
