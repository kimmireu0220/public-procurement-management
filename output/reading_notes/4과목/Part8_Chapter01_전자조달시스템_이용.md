## 한눈에 보는 구조

`등록 → 발주계획·사전규격·공고 탐색 → 입찰 → 전자계약 → 이행·검사검수 → 대금청구·지급 → 오류 대응`

| 단계 | 핵심 확인 |
|---|---|
| 등록 | 이용자, 기업, 입찰대리인, 인증서, 참가자격 |
| 탐색 | 발주계획, 사전규격, 공고와 첨부파일 |
| 입찰 | 자격·권한·파일·금액·마감·접수결과 |
| 계약 | 초안, 수정 요청 또는 응답, 양측 전자서명 |
| 이행·대금 | 이행, 검사·검수 합격, 청구, 지급 |
| 오류 | 확인, 원인 구분, 환경 점검, 재실행, 공식 문의 |

## 핵심 내용

### 1. 전자조달시스템과 이용주체

나라장터는 발주계획, 사전규격, 입찰공고, 입찰서 제출, 개찰·낙찰, 전자계약, 검사·검수, 대금청구를 연결하는 국가종합전자조달시스템이다. 전자화의 목적은 업무 효율뿐 아니라 투명성·공정성·경쟁성 및 이력관리에 있다.

- 발주기관 조달담당자: 계획·공고를 등록하고 입찰·계약을 관리한다.
- 조달기업: 공고 검색, 자격 확인, 입찰, 계약이행, 대금청구를 한다.
- 입찰대리인: 기업을 대표해 적법하게 등록된 권한으로 전자서명을 수행한다.
- 수요기관: 이행결과를 검사·검수하고 지급절차를 진행한다.

### 2. 이용자·자격 등록

박문각의 이용 흐름은 `개인회원 등록 → 로그인 → 조달업체 등록 또는 소속업체 선택 → 사업자용 공동인증서 등록 → 전자입찰·계약·청구 이용`이다.

사용자 등록과 입찰참가자격 등록은 다르다. 로그인할 수 있어도 공고가 요구하는 업종, 품목, 면허, 실적 등을 충족하지 못하면 참여할 수 없다. 상호, 대표자, 주소, 입찰대리인, 업종·품목 정보는 상시 최신 상태로 관리한다.

### 3. 발주계획·사전규격·공고 탐색

- 발주계획: 사업 개요, 예산, 추진시기를 보고 생산·인력·자금·인증의 준비기간을 계산한다.
- 사전규격: 자사 제품·수행능력과의 적합성을 검토하고 과도하거나 불명확한 조건에는 정해진 절차로 의견을 낸다.
- 입찰공고: 참가자격, 계약방법, 평가기준, 제출기간, 보증, 공동수급, 낙찰자 결정방법, 서류별 마감, 계약기간, 장소, 검사·지급조건을 확인한다.

공고는 물품·용역·공사, UNSPSC 상품분류코드, 입찰방식, 규모, 발주기관 등으로 검색할 수 있다. 제목만으로 참여를 결정하지 않고 공고문과 첨부파일을 모두 확인한다.

### 4. 법규 검색과 실적제한 사례

법규는 `법률 → 시행령 → 시행규칙 → 계약예규·집행기준` 순으로 확인한다. 최신 조문은 국가법령정보센터에서 확인하고 조달청 종합민원센터의 질의·사례를 참고할 수 있다.

표준교재 사례는 10억원 물품 입찰에 20억원 납품실적을 요구한 경우다.

1. 국가계약법 시행령 제21조: 실적으로 경쟁참가자를 제한할 수 있는 근거 확인
2. 시행규칙 제25조: 고시금액 이상 입찰의 실적요건은 계약목적물 규모·양의 **1배 이내**
3. 정부 입찰·계약 집행기준 제5조: 실적요건은 원칙적으로 계약목적물 규모의 **3분의 1배**가 적정

20억원은 10억원의 2배이므로 1배 상한을 넘는다. 기업은 사전규격 공개기간에 의견을 제출하고, 발주기관은 제한조건을 법령에 맞게 수정해야 한다.

### 5. 전자입찰

`마감 확인 → 인증서·대리인 권한·참가자격 확인 → 파일 형식·용량·전자서명 확인 → 입찰금액 내부자료와 대조 → 여유 있게 제출 → 접수결과 확인`

마감 후에는 제출할 수 없다. 개찰 뒤에도 최저가격만으로 항상 계약상대자가 되는 것은 아니며 공고에 따라 적격심사, 제안서 평가, 협상 등이 이어질 수 있다.

### 6. 전자계약, 이행과 대금

`발주기관의 계약서 초안 송신 → 계약상대자의 검토 → 내용이 다르면 수정 요청 / 문제가 없으면 계약응답·전자서명 → 발주기관 전자서명 → 계약 확정`

계약상대자는 금액, 기간, 범위, 보증, 지체상금, 검사, 지급, 변경조건을 확인한다. 선금은 계약 이행에 필요한 자금을 미리 지급하는 제도이며 신청·사용·정산은 계약조건과 기준을 따른다.

계약 확정 후에는 `계약상대자 이행 → 수요기관 검사·검수 → 합격 → 계약상대자 대금청구 → 발주기관 확인·지급`으로 진행한다.

### 7. 연계 플랫폼

| 플랫폼 | 용도·절차 | 박문각 수험서 기준 숫자 |
|---|---|---|
| 종합쇼핑몰 | 단가계약·MAS 상품 검색 → 장바구니 → 조달요청서 → 납품요구 → 납품 | 별도 고정값 없음 |
| 벤처나라 | 창업·벤처기업 제품 판로, 추천 → 신청 → 심사 → 지정 → 상품등록·지정증서 | 창업 7년 이내, 일반 2천만원 이하·사회적기업 등 5천만원 이하 구매, 지정제품 6년 |
| 혁신장터 | 혁신제품 정보·시범구매·혁신수요 연결 | 수의계약 가능기간 최대 3년 |
| 디지털서비스몰 | 클라우드 등 디지털서비스, 수의·카탈로그계약 | 서비스 기능·가격 등록 → 제안평가·협상 → 계약 |
| 이음장터 | 공공기관·민간기업의 소규모 서비스 직접협상 | 일반 2천만원 이하·사회적기업 등 5천만원 이하 |

이음장터 절차는 `수요 등록 → 공급업체 응답 → 계약 → 서비스 제공 → 대금지급`이다.

위 금액과 기간은 **박문각 수험서 이론 기준이며 표준교재 제8장에는 수록되지 않았다. 실제 거래 시 최신 운영기준과 공고를 확인한다.**

### 8. 오류 대응

오류는 다섯 유형이다.

- 인증서 오류
- 보안프로그램 오류
- 입찰서 제출 오류
- 시스템 접속 장애
- 데이터 입력 오류

대응은 `오류 메시지·시각·업무 확인 및 화면 기록 → 원인 구분 → 인증서·권한·프로그램·네트워크·입력값 점검 → 안내 방식으로 재실행 → 공식 문의창구 문의` 순이다. 마감 전 사전점검과 여유 있는 제출이 가장 중요한 예방책이다.

## 실무 절차(누가·언제·무엇)

| 시점 | 주체 | 할 일 |
|---|---|---|
| 상시 | 기업·입찰대리인 | 등록정보, 권한, 인증서, 참가자격 최신화 |
| 입찰 전 | 발주기관 | 발주계획·사전규격·공고 공개 |
| 탐색·검토 | 기업 | 사업기회, 법적 제한, 수행능력, 제출조건 검토 |
| 마감 전 | 입찰담당자 | 서류·금액·서명 확인 후 제출·접수 확인 |
| 낙찰 후 | 발주기관·계약상대자 | 초안 검토, 수정 요청 또는 응답, 양측 서명 |
| 이행 후 | 계약상대자·수요기관 | 이행, 검사·검수, 청구·지급 |
| 장애 발생 | 이용자 | 증거 보존, 원인 점검, 재실행, 공식 문의 |

## 비교·주의사항

- 사용자 등록과 입찰참가자격 등록을 혼동하지 않는다.
- 공고 제목이 아니라 본문·첨부파일·마감시각을 확인한다.
- 제한의 근거, 상한, 적정기준은 서로 다른 규정에서 찾는다.
- 전자계약도 권리·의무를 확정하는 계약이므로 검토 없이 서명하지 않는다.
- 계약서 초안과 공고·협상결과가 다르면 서명 전 수정 요청을 한다.
- 플랫폼 숫자는 박문각 기준과 표준교재 기준을 구분한다.
- 시스템 장애 가능성을 이유로 마감 직전까지 제출을 미루지 않는다.

## 최종 정리

전자조달은 `등록 → 탐색 → 입찰 → 계약 → 이행·대금 → 오류 대응`으로 이해한다. 각 단계에서 주체와 권한, 자격, 마감, 접수결과를 확인한다. 제한조건은 시행령의 근거, 시행규칙의 1배 상한, 집행기준의 3분의 1배 적정기준으로 검토한다. 전자계약은 수정 요청과 양측 서명을 포함하며, 이행 후 검사·검수 합격을 거쳐 대금을 청구한다.

오류 다섯 유형은 `인증서, 보안프로그램, 입찰서 제출, 시스템 접속, 데이터 입력`이다.
